# V20 失败归因与 LightGlue 后二维几何验证方案

建议下一步推进 **LightGlue → F-MAGSAC++ 对应验证 → 现有 PnP** 的独立小规模对照。
使用 V19 原始深度，不叠加 V20 时间补偿。当前最需要回答的是“二维几何一致性筛选
能否优于任意减少对应带来的采样变化”，而不是继续提高 PnP 接受数。

本文只分析已有输出并冻结候选方案，没有运行 F/H 估计、重新匹配或新位姿实验。

## 时间补偿为什么没有稳定收益

### 1. 实际可用运动源没有诊断中的真值运动那么可靠

V20 只使用原估计轨迹。teddy158 的时间间平移估计为 27.91 mm，先前事后真值诊断为
3.35 mm；转角为 0.964° 对 1.481°。时间戳正确，不等于用于校正的运动正确。
另一个例子 teddy203，在约 12.66 ms 时间差内产生 279.92 mm 的估计运动，说明该
历史序列的局部运动不能仅凭 `valid` 标签认定可靠。

读取现有估计器代码可见，`pose_valid=true` 在原生相对位姿成功后设置；它表示通过
估计器接受条件，并不是短时运动准确性证明。帧记录直接写入 `result.frame` 的原始
估计位姿，当前证据不支持把这次异常归因于把 BA 校正历史混作原始轨迹。

### 2. 先前发现的是时间因素，不是“时间因素解释全部错误”

即便将固定真值取在深度时刻检查原深度，teddy158-159 公共网格残差中位数仍约
5.14 cm。遮挡、空间配准、标定模型和错误对应仍可能存在。当前最近像素重投影也不
处理这些问题；不能通过加大时间补偿幅度来统一修复。

### 3. 准确数增加首先来自对应子集变化

V19 完整输入有 11455 个源端深度有效对应，共同子集为 10315，减少 9.95%。不补偿
深度，仅用这个共同子集，准确数就从 15/39 变为 16/39；补偿后仍为 16/39。
desk22-23、room141-143、room142-143 的准确恢复已经出现在未补偿共同子集上。

点的减少同时改变了原生 RANSAC 的输入和抽样，不能仅凭这些恢复认定深度质量筛选
已经奏效。以 room141-143 为例，从 45 个输入删掉一个，未补偿结果已经从 3.20 cm
变为 1.31 cm，而随后深度补偿变化很小。

### 4. 同观测补偿存在清楚的收益/损失交换

| 指标 | V19 完整输入 | 未补偿共同子集 | 时间补偿共同子集 |
| --- | ---: | ---: | ---: |
| 准确，须同时通过两种 GT 对齐 | 15/39 | 16/39 | 16/39 |
| 新增退化 | 7 | 4 | 3 |
| 保留 V19 原八对获益 | 8/8 | 4/8 | 3/8 |
| Interpolated 平移 P95 | 15.40 cm | 14.94 cm | 16.16 cm |

补偿相对未补偿共同子集有三对准确性收益、三对损失。xyz23-26 的深度变化中位数
仅约 1.2 mm，但平移误差从 1.80 cm 到 4.29 cm；其内点集合 Jaccard 为 0.792，
平均拟合重投影误差还从 1.649 降到 1.624 px。较低拟合残差并没有保证正确位姿。
desk21-24 的两组内点数都是 29，交集只有 18（Jaccard0.45），反映共识集合变化。

因此，现有运动源 + 当前深度注册的组合没有形成稳定额外收益。此结论不否定一切
时间对齐方法，但当前不值得继续围绕其门限修补。

## 为什么值得验证 MAGSAC++，它能解决什么

LightGlue 提供描述子/上下文匹配，下一项可独立检验的信号是整对图像的二维几何
一致性。F 验证不依赖源端深度或历史估计运动，可以在构造三维对应前，先检查一组
匹配是否服从同一对极模型。它也无需在这一层引入新的内参估计。

已有事后诊断显示，teddy158-159、158-160 的原 PnP 内点中，满足真值 Sampson 误差
≤3px 的比例为 27.6%、47.1%；teddy110-112 为 42.9%。这些是值得验证二维一致性的
线索，而非可靠的逐点误匹配标签：例如成功的 xyz24-26 也只有约 27.8%，投影模型、
真值差异及评价容差均会影响这一诊断。不得按真值残差筛选实际推理输入。

OpenCV 已提供 `USAC_MAGSAC`，官方实现将其对应到 MAGSAC++。虽然评分对噪声尺度作
边缘化，OpenCV 的终止等环节仍使用给定阈值，不能声称使用它就完全没有阈值。
[OpenCV USAC 文档](https://docs.opencv.org/4.13.0/de/d3e/tutorial_usac.html)；
[MAGSAC 官方工程](https://github.com/danini/magsac)

本机既有 OpenCV5.0.0 可见 `findFundamentalMat` 和 `USAC_MAGSAC` 接口，本轮只检查了
接口存在，没有调用估计器，无需为这一候选安装新依赖。

它不能修正深度错误、RGB-D 时序、镜头畸变，F 模型在平面主导或低视差条件下也可能
缺少判别力。因此不能把“估出了 F”或“F 内点更多”当作位姿收益，更不能把它当成
原生 PnP 的替代方法。

## 冻结的下一步对照方案

### 输入与处理顺序

1. 复用 V19 全部39对、25张图像的缓存 RootSIFT 特征和 LightGlue 匹配，不重新推理。
2. 在**全部二维匹配**上估计 F，不先筛源深度，也不使用原始/真值位姿选模型。
3. 将 F 内点掩码与 V19 原始源端深度有效行相交，保留原特征 ID 和源索引排序。
4. 使用原始、未时间补偿的深度，以及相同相机、原生 PnP 二进制和参数估计位姿。

固定参数：`USAC_MAGSAC`、像素参数3.0、confidence0.999、maxIters10000；记录本地实际
版本和配置，只运行一个预先固定的 F 配置，不扫参。PnP 仍为 V19 原生配置、requested
seed17。F/H 设置 requested 全局 seed17，并记录实际接口行为；不把全局 seed 设置
当成独立随机试验保证，也不会把改变 requested seed 宣称为改变了旧 PnP 的采样器。

F 拟合失败、非法输出、验证后不足6个源端三维对应、PnP拒绝，均记录区别明确的失败
原因并返回精确 raw 位姿。F 拟合输入不足8条单独拒绝。不得把失败退回全部匹配后仍
算作“经过几何验证”。所有39对一直保留在结果分母中。

### 基线和必要的子集控制

| 组别 | 对应来源 | 新原生 PnP 调用 |
| --- | --- | ---: |
| A：V19 原完整输入 | 复用冻结结果 | 0 |
| B：F-MAGSAC++ 验证 | F 内点与原源深度有效行的交集 | 39 |
| C17/C23/C41：等量子集 | 从原源深度有效行选出与 B 相同数量的对应 | 117 |

三个 C 控制用预先固定的 NumPy 子集选择种子17、23、41，均匀无放回选择，再按原源
特征索引排序。这里改变的是**输入子集**，确实与旧 PnP 内部固定 RNG 的重复调用不同。
全部控制都报告，不挑选最佳 seed。B 的数量未知/验证失败时，C 标记控制不可定义并
返回 raw，不能将该情况解释成已完成数量效应比较；整体39对分母仍保留。

这个控制专门排除 V20 已暴露的替代解释：看起来改善的可能只是删点改变了共识抽样。
预计最多156次新原生 PnP调用，旧结果全部复用，没有 LightGlue 推理或训练。

### H 只作退化诊断

另在相同全部二维匹配上用固定参数估计 H，保存支持、空间覆盖和重投影残差，帮助
解释 room 的平面主导情形。本阶段 H 不选取实际 PnP 输入、不产生相机位姿，也不新增
H/F 比例硬门控。F 的 Sampson 误差与 H 的重投影误差不是同一个统计量，不能直接按
内点计数或未经标定的比例比较后决定哪个模型“正确”。

### 评价与推进条件

首要评价仍为两种真值对齐都满足3cm/2°的准确位姿数、原始准确位姿新增退化、原八对
获益保留、准确应用数和完整连续误差尾部。所有 F/H 掩码、失败、深度损失、图像支撑、
耗时和内存均保存。GT 仍只在拟合封存后评价。

值得继续推进，需要同时看到：B 相对 V19 准确数增加、新增退化减少，且收益优于三个
等量控制的典型表现；原八对获益损失须逐对明确。还要与 V20 的16/39、3对退化作
实际取舍比较，不能只拿较弱基线作排名。若只比 V19 好、与任意等量子集相当，应归因于
输入选择/采样效应，不能宣称几何验证机制已经有效。

若二维一致性明显改善但位姿不改善，证据将指向深度/投影模型或三维支撑，而不是继续
增加匹配数或扩大 MAGSAC 扫参。本阶段只做离线候选筛选，不自动接入 BA 或在线跟踪。

## 当前交付边界

本轮完成失败归因、接口存在性检查和上述方案。没有运行 MAGSAC、H、PnP 或新的匹配
实验，也没有修改 V19/V20 结果。可执行配置摘要见
[候选协议](../results/magsac_verification_plan.json)。

累计贡献是已有原生后端、共享特征匹配对照、同观测时间控制，以及本方案针对输入子集
效应的控制设计。下一项工程收益应由实际准确位姿与退化变化证明，不需要另建算法体系。
