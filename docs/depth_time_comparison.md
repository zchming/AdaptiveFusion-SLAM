# V20：已有估计轨迹驱动的源端深度时间补偿

源端时间补偿已实现，39 对输入的同观测对照完成。**当前不采用为默认方案：在相同
对应上，补偿前后均为 16/39 准确，补偿产生三对准确性收益和三对损失。** 新增退化从
4 对减少到 3 对，但 V19 原有八对获益的保留数从 4 降到 3。此前时间诊断指出的因素
确实值得检查，却没有转化成当前估计轨迹下稳定的额外准确率收益。

## 实现与数据边界

新增 `adaptivefusion/depth_time_alignment.py` 与
`python/run_depth_time_comparison.py`。补偿输入仅为原估计轨迹 `frames.txt`、时间戳、
原深度、冻结的 V19 LightGlue 对应。运行清单只接受 `frames`、`features` 字段，
不接受真值或评价路径。

估计轨迹中相邻有效帧的 T_wc 平移线性插值、旋转 SO(3) Slerp；不外推，不跨 lost
帧插值。实际插值帧 ID 与区间长度逐源帧记录。深度时刻 td 到 RGB 时刻 tr 的运动为：

`T_c(tr)_c(td) = inverse(T_wc(tr)) @ T_wc(td)`。

使用原历史内参 [517.3,516.5,318.6,255.3]，将空间已预配准的深度转为米，反投影、
应用上述时间运动、最近像素重投影并取最近 Z。保持空洞，不膨胀、不补洞，不重施
RGB/IR 外参或 1.035 尺度修正。输出按原 5000 单位/m 四舍五入到 uint16。

共同有效对应为 V19 原有效行与补偿深度有效行的交集；两种表示均用原 `sample_depth`
3x3 全非零、深度跨度 ≤0.05 m 规则，未额外引入深度上下界。目标深度不参与筛选。

原生 PnP 二进制、参数及 requested seed17 不变。V19 源数据、原始位姿及二进制通过
其既有来源哈希绑定。新拟合结果和输入封存后，才单独调用既有 GT 评价器。
GT 从未用于时间补偿、对应选择或插值运动。

### 首轮插值限制的修正与失败保留

首轮额外加入了 50 ms 插值跨度上限，导致 desk 六对拒绝，虽然这些位置有相邻有效
估计帧，实际间隔约 67.9 ms。这是实现额外增加的限制，并非原方案要求。
依据估计轨迹时间戳移除该限制，恢复原方案“相邻有效帧支撑”的规则，同时显式记录
跨度。修正并非按准确率挑选阈值。

首轮全部 39 对、156 条评价记录和 16 次 raw 回退均保留在证据目录 `study/`、
`evaluation/`，修正后结果另存 `study-final/`、`evaluation-final/`。两版源代码快照
均保留，首轮快照与其记录哈希一致。修正后 desk 新执行 12 次 PnP；其余 33 对的 66
个输入逐项完全相同，直接复用已封存结果和原生报告，没有重复运行。

## 为什么实际补偿没有稳定收益

已有轨迹的瞬时运动本身不一定可靠。仅在拟合封存、评价完成之后，结合上轮保存的
时间诊断作解释：源帧 teddy158 的估计时间间运动平移为 27.91 mm，真值诊断为
3.35 mm；估计转角为 0.964°，真值为 1.481°。估计运动用于补偿，真值仅用于这里的
事后对照，未据此调参或重跑。不能期望不可靠的短时估计运动自动恢复可靠的深度关联。

先前使用深度时刻真值进行的诊断仍留下明显深度不一致，因而时序也不是唯一解释。
本轮明确验证了可部署的这一种方案——原始估计轨迹插值、最近像素前向深度注册——
没有额外提高同观测准确数；不能据此声称所有时间对齐方法都无效。

当前保持 V19 和原始位姿为参照，不替换默认输入，不继续调整补偿阈值。MAGSAC、
其他二维几何验证、BA 与在线跟踪均未接入；后续工作另按授权阶段进行。

## 成本、验证与复现

19 个独立源帧的读取、补偿和深度缓存写入合计 0.671 s，CPU 执行，无新匹配推理。
修正后运行阶段 4.193 s，包含 12 次新 worker 和 66 个缓存结果复用；不能将它当作
78 次全新拟合速度。两组原始 worker 测时分别合计 9.506 /9.434 s，峰值 RSS
81.05 /81.22 MiB。首次运行和修正成本均留在原始日志中。

只进行了五项相关验证：恒等补偿精确保留深度与空洞、前向投影/Z-buffer 及单位、
变换方向、旋转插值与 lost 帧拒绝、不外推与显式可选跨度限制。未重复全量回归。

```sh
python python/run_depth_time_comparison.py \
  --baseline-study "$V19_STUDY" --trajectory-study "$V18_STUDY" \
  --sources "$ESTIMATED_MOTION_SOURCES_JSON" \
  --native-binary "$NATIVE_PNP" --output "$NEW_STUDY"
python python/run_camera_pnp_comparison.py evaluate \
  --study "$NEW_STUDY" --sources "$EVALUATION_SOURCES_JSON" \
  --output "$NEW_EVALUATION"
```

1，所有输出目录必须全新。可选 `--reuse-study` 仅复用二进制相同且输入逐项相同的
已封存原生拟合。
